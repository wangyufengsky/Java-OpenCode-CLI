# AgentBridge 任务控制台 UI/UX 改版设计

## 1. 背景

当前任务控制台由 Spring MVC、Thymeleaf、原生 JavaScript 和 CSS 构成，包含运行概览、新建运行、运行详情、运行历史和定时任务五类页面。现状能够完成基本操作，但存在以下问题：

- 页面缺少统一的常驻导航，用户需要依赖各页面顶部按钮往返。
- 新建运行会一次展示大量链路配置，默认值、必填项和高级设置缺少层次。
- 运行详情把指标、事件和任务并列展示，失败原因与下一步操作不够突出。
- 历史记录缺少搜索和筛选，无法快速复用历史配置。
- 定时任务的计划、启停和创建表单混在同一信息层级中，下一次执行时间不直观。
- 加载、空结果、连接中断和操作失败缺少一致的反馈模式。

## 2. 目标与边界

### 2.1 目标

围绕“创建 → 运行 → 排障 → 重跑或复用”的任务生命周期统一优化五类页面，使高频操作更快、运行状态更清楚、失败处理更直接。

### 2.2 成功标准

- 用户能从任意页面一步进入新建运行、历史记录或定时任务。
- 复杂链路配置按业务分组展示，默认值、必填项和高级项可以被快速识别。
- 运行失败时，首屏直接展示失败阶段、失败任务、错误摘要和建议操作。
- 历史运行可以按关键字、状态、链路和日期筛选，并可复制配置创建新运行。
- 定时任务明确显示启用状态、执行频率和下一次执行时间。
- 五类页面使用相同的状态、反馈、筛选和列表操作规则。

### 2.3 范围

本次覆盖：

- 五类现有页面的 Figma 设计与前端实现。
- Thymeleaf 页面结构、CSS 和原生 JavaScript 的重构。
- 支持历史筛选、运行摘要和配置复用所需的少量后端能力。
- 桌面端 1280–1600 像素宽度的布局与视觉验证。

本次不覆盖：

- React、Vue、CSS 框架或新的前端构建系统。
- 工作流执行核心、AgentBridge 调度协议和链路配置格式的变更。
- 完整移动端交互设计。
- 取消运行、批量运行、批量删除和结果导出等深度运维能力。

## 3. 设计方向

采用“专业运营工作台”视觉方向：深色常驻侧栏、浅色内容区域、蓝色主操作、清晰的状态色和中等信息密度。

主要视觉原则：

- 页面背景使用冷灰色，内容卡片使用白色，降低长时间使用的视觉负担。
- 侧栏使用深蓝色，当前导航项使用较亮的蓝灰背景。
- 主操作使用品牌蓝；成功、警告、失败分别使用绿、橙、红语义色。
- 状态不能只依赖颜色，还需同时使用图标或文字。
- 页面主标题、状态摘要、主要操作、详细数据依次形成稳定层级。
- 布局以 1440 像素桌面端为基准，同时验证 1280 和 1600 像素宽度。

## 4. 信息架构

### 4.1 统一页面框架

所有页面共享以下结构：

1. 常驻侧栏：产品标识、运行概览、新建运行、运行历史、定时任务和服务状态。
2. 页面头部：面包屑、页面标题、辅助说明和不超过两个主要操作。
3. 内容区域：使用统一的卡片、指标、筛选和状态组件。

侧栏替代现有页面中重复的顶部导航按钮。服务状态只显示当前 AgentBridge 连接状态和必要说明，不扩展为独立运维子系统。

### 4.2 页面职责

| 页面 | 核心问题 | 主要内容 |
| --- | --- | --- |
| 运行概览 | 系统现在是否健康，我接下来要处理什么 | 今日运行、执行中、成功率、需要关注、最近运行、异常提醒、快捷启动 |
| 新建运行 | 如何安全、快速地完成复杂配置 | 工作流选择、分组配置、运行摘要、提交前检查 |
| 运行详情 | 当前执行到哪里，失败后该做什么 | 状态摘要、阶段进度、失败摘要、任务列表、实时事件、重跑入口 |
| 运行历史 | 如何找到、比较和复用过去的运行 | 搜索、筛选、运行列表、查看详情、复制配置 |
| 定时任务 | 哪些计划会在什么时候执行 | 计划列表、启停状态、下次执行、创建、编辑、复制 |

## 5. 页面设计

### 5.1 运行概览

首屏依次展示：

1. 四个概览指标：今日运行、执行中、近七天成功率、需要关注。
2. 最近运行列表：显示链路、运行 ID、项目、状态、阶段或进度、耗时和查看入口。
3. 需要关注：聚合最新失败运行，展示失败阶段和进入排障的入口。
4. 快捷启动：从常用链路或已保存配置创建运行。

概览页只展示有限数量的最近运行和异常，完整数据进入历史页。快捷启动进入带入默认值或历史配置的新建运行页，不在概览页直接提交任务。

### 5.2 新建运行

页面使用“选择工作流、配置参数、确认并运行”三个连续阶段，但所有阶段位于同一页面，避免多页向导打断上下文。

主要交互：

- 最近使用的工作流优先展示，其余工作流可展开选择。
- 选择工作流后，通过现有默认值接口加载链路配置。
- 配置字段按业务分组，而不是按原始键名平铺。
- 默认值显示来源标记；必填项显示明确标记和字段级说明。
- AgentBridge、覆盖率和链路调优参数归入可折叠的高级设置。
- 右侧运行摘要固定展示工作流、模式、目标项目、扫描范围和提交前检查。
- 提交成功后跳转到新运行的详情页。

重跑模式根据链路能力动态展示重跑类型。仅需要 ID 的类型展示 ID 输入；“总报告”“验证”等无需 ID 的类型不显示无效输入框。

复制历史配置时，页面必须明确标识来源运行，并允许恢复当前链路默认值。复制只创建新的表单草稿，不修改原运行。

### 5.3 运行详情

页面从上到下依次展示：

1. 运行标识、状态和主要操作。
2. 状态摘要：失败或运行中的关键结论、耗时、任务进度和运行模式。
3. 阶段进度：准备、任务生成、Agent 执行、验证和报告。
4. 失败摘要：失败任务、错误摘要、失败阶段和建议操作。
5. 实时事件与任务列表。

失败运行默认把失败任务置顶。失败摘要来源于已持久化的运行状态、任务状态和最近错误事件，不依赖生成式推断。若信息不足，使用“请查看完整错误事件”而不是编造原因。

主要操作包括复制配置和按现有重跑契约重跑失败单元。页面不新增取消运行能力。

实时事件支持全部、阶段、任务和错误四类筛选。SSE 正常时显示已连接状态；中断时显示正在重连，并降级为定时刷新。事件按 ID 去重，避免重连后重复插入。

### 5.4 运行历史

筛选栏包含：

- 运行 ID、项目名或链路关键字。
- 状态。
- 链路。
- 日期范围。

筛选使用 GET 查询参数，页面刷新后条件保持不变。服务端完成筛选，前端不在完整结果集上做隐藏式过滤。

每行显示运行 ID、链路、项目、模式、状态、开始时间、耗时和操作。行操作包括查看详情和复制配置。首版不提供批量选择与批量操作。

### 5.5 定时任务

列表显示计划名、链路、模式、执行频率、下一次执行时间、启用状态和操作菜单。

交互规则：

- 启停操作立即反馈成功或失败，失败时恢复原状态。
- 创建与编辑使用右侧抽屉，复用新建运行页的字段分组和校验规则。
- 支持复制现有计划生成新计划草稿。
- 一次性计划执行后显示“已执行”，不再显示误导性的下一次时间。

首版不提供批量启停或删除。

## 6. 组件与前端结构

### 6.1 Thymeleaf 组件

抽取可复用 fragment：

- 应用壳层和侧栏。
- 页面头部。
- 状态标签。
- 指标卡。
- 空状态、错误状态和加载状态。
- 筛选栏。
- 表单分组和字段错误。

### 6.2 CSS 结构

现有单一样式文件按以下职责重组，仍通过静态资源直接加载：

- 设计令牌：颜色、间距、圆角、阴影、字体和层级。
- 基础样式：重置、排版、链接和可访问焦点。
- 布局：侧栏、页面头部、内容网格和桌面宽度约束。
- 组件：按钮、输入框、卡片、状态、表格、提示和抽屉。
- 页面样式：概览、新建运行、运行详情、历史和定时任务。

### 6.3 JavaScript 结构

不引入模块打包器。使用多个静态脚本按页面加载：

- 公共脚本：请求封装、消息反馈、状态映射和格式化。
- 新建运行脚本：链路选择、默认值、动态字段、分组、校验和摘要。
- 运行详情脚本：SSE、重连、事件去重、任务筛选和定时刷新降级。
- 历史脚本：筛选条件同步与配置复用入口。
- 定时任务脚本：抽屉表单、启停、创建、编辑和复制。

字段定义保持数据驱动，并补充分组、是否必填、是否高级字段和摘要展示等元数据。字段键和后端配置契约保持不变。

## 7. 后端配套能力

只增加控制台展示所需能力：

- 历史列表支持关键字、状态、链路和日期查询参数。
- 运行详情提供可直接展示的运行摘要，包括任务计数、耗时、失败阶段和最近错误事件。
- 提供读取历史运行配置的能力，用于复制配置到新建运行页。
- 提供只读的本地路径预检查，用于提示路径是否可访问以及是否存在 `pom.xml` 等项目标记；预检查不改变提交接口的校验规则。
- 定时任务返回计算后的下一次执行时间和一次性任务执行状态。

这些能力优先通过现有控制器、仓库和服务扩展完成，不改变工作流执行器、链路契约或持久化事件语义。

## 8. 数据流

1. 服务端渲染页面的初始数据和当前筛选条件。
2. 新建运行页按链路请求默认值，前端生成分组字段并维护运行摘要；路径输入停止变更后触发只读预检查。
3. 表单提交现有运行 API；成功后跳转详情，失败时保留用户输入并展示错误。
4. 运行详情连接 SSE 获取增量事件，同时以持久化状态作为页面真值。
5. SSE 重连失败时定时请求运行摘要和事件增量，恢复后停止轮询。
6. 历史筛选提交 GET 参数，由服务端查询后重新渲染。
7. 复制配置读取历史配置，将其作为新建页初始草稿。
8. 定时任务沿用现有 API，补充下一次执行时间和编辑所需数据。

## 9. 错误与反馈

- 字段错误显示在对应输入附近，页面顶部同时提供可定位的错误摘要。
- 默认配置读取失败时允许手工填写，并明确说明默认值不可用。
- 路径预检查失败只显示风险提示，不阻止用户继续编辑；最终是否允许提交仍由现有提交接口校验契约决定。
- API 操作统一展示进行中、成功或失败状态，避免重复提交。
- 启停失败必须恢复开关的原值。
- 空列表、无筛选结果、加载中、连接中断和服务错误分别使用不同状态。
- 键盘焦点清晰可见；抽屉打开后焦点进入抽屉，关闭后返回触发按钮。

## 10. Figma 交付

Figma 文件包含：

- Foundations：颜色、字体、间距、圆角、阴影和栅格。
- Components：按钮、输入框、选择器、状态标签、卡片、指标、筛选栏、表格行、提示、抽屉和阶段进度。
- Screens：1440 像素宽度的运行概览、新建运行、运行详情失败态、运行历史和定时任务。
- States：加载、空结果、API 失败、SSE 重连和字段校验错误。

页面设计使用自动布局和统一组件实例。Figma 设计确认后再实施代码，并在实现完成后对照设计进行视觉复核。

## 11. 验证策略

### 11.1 自动验证

- 扩展 `ConsoleMvcTest`，覆盖新页面结构、历史筛选、运行摘要、配置复用和定时任务下一次执行时间。
- 将纯 JavaScript 数据转换与表单规则拆成无 DOM 依赖的函数，并在浏览器主流程检查中直接验证输入、输出与页面联动。
- 保留现有运行提交、重跑契约、默认配置和 SSE 测试。
- 运行完整 Maven 测试，并执行 `git diff --check`。

### 11.2 浏览器验证

验证以下主流程：

1. 从概览页选择快捷入口并创建运行。
2. 切换链路后默认值、字段分组和摘要正确更新。
3. 提交失败时输入不丢失，成功时跳转详情。
4. 详情页接收事件、更新状态，并在断线后重连或降级刷新。
5. 历史筛选可刷新保持，复制配置可生成新草稿。
6. 定时任务可创建、编辑、复制和启停。

在 1280、1440 和 1600 像素宽度下检查文本截断、表格溢出、抽屉遮挡和主要操作可见性。

## 12. 实施约束

- 不覆盖当前工作区中与本改版无关的未提交改动。
- 不改变现有配置键、重跑类型和工作流执行语义。
- 新增文案继续使用中文，并复用 `ConsoleText` 中已有的状态和链路名称映射。
- 先完成并确认 Figma 设计，再实施前端和配套后端改动。
- 实现完成后，Figma、模板、JavaScript、CSS、控制器和测试中的状态文案必须一致。
